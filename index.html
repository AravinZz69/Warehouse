⚠️ MySQL → Supabase migration: Replace all mysql+pymysql:// connection strings with Supabase PostgreSQL URI. Replace INT AUTO_INCREMENT with SERIAL or BIGSERIAL. Replace TINYINT(1) booleans with BOOLEAN. All DATETIME → TIMESTAMPTZ. All TEXT columns remain the same.

Supabase Schema — New Tables

Run these in Supabase SQL Editor. Do not touch existing CoreInventory tables.

⚠️ Run the ALTER TABLE first before any inserts. All new tables use BIGSERIAL primary keys and TIMESTAMPTZ for timestamps — no MySQL-style AUTO_INCREMENT.
SQL — Supabase SQL Editor 
-- Step 1: Alter existing stock_levels table
ALTER TABLE stock_levels
  ADD COLUMN IF NOT EXISTS reserved_qty INTEGER DEFAULT 0;

-- Step 2: Customer orders
CREATE TABLE customer_orders (
  id            BIGSERIAL PRIMARY KEY,
  order_number  VARCHAR(20) UNIQUE NOT NULL,
  customer_name VARCHAR(100) NOT NULL,
  customer_email VARCHAR(150),
  customer_address TEXT,
  priority_score FLOAT DEFAULT 0.0,
  priority_label VARCHAR(10) DEFAULT 'medium',
  sla_deadline   TIMESTAMPTZ,
  status         VARCHAR(30) DEFAULT 'created',
  notes          TEXT,
  created_by     INTEGER REFERENCES users(id),
  created_at     TIMESTAMPTZ DEFAULT NOW(),
  updated_at     TIMESTAMPTZ DEFAULT NOW()
);

-- Step 3: Order lines
CREATE TABLE order_lines (
  id            BIGSERIAL PRIMARY KEY,
  order_id      BIGINT REFERENCES customer_orders(id) ON DELETE CASCADE,
  product_id    INTEGER REFERENCES products(id),
  warehouse_id  INTEGER REFERENCES warehouses(id),
  requested_qty INTEGER NOT NULL,
  allocated_qty INTEGER DEFAULT 0,
  picked_qty    INTEGER DEFAULT 0,
  packed_qty    INTEGER DEFAULT 0,
  status        VARCHAR(25) DEFAULT 'pending'
);

-- Step 4: Allocations
CREATE TABLE order_allocations (
  id            BIGSERIAL PRIMARY KEY,
  order_id      BIGINT REFERENCES customer_orders(id),
  order_line_id BIGINT REFERENCES order_lines(id),
  product_id    INTEGER REFERENCES products(id),
  location_id   INTEGER REFERENCES locations(id),
  reserved_qty  INTEGER NOT NULL,
  status        VARCHAR(15) DEFAULT 'reserved',
  allocated_at  TIMESTAMPTZ DEFAULT NOW()
);

-- Step 5: Picking tasks
CREATE TABLE picking_tasks (
  id            BIGSERIAL PRIMARY KEY,
  order_id      BIGINT REFERENCES customer_orders(id),
  order_line_id BIGINT REFERENCES order_lines(id),
  product_id    INTEGER REFERENCES products(id),
  location_id   INTEGER REFERENCES locations(id),
  assigned_to   INTEGER REFERENCES users(id),
  requested_qty INTEGER NOT NULL,
  picked_qty    INTEGER DEFAULT 0,
  status        VARCHAR(15) DEFAULT 'pending',
  failure_reason TEXT,
  started_at    TIMESTAMPTZ,
  completed_at  TIMESTAMPTZ,
  created_at    TIMESTAMPTZ DEFAULT NOW()
);

-- Step 6: Packing records
CREATE TABLE packing_records (
  id              BIGSERIAL PRIMARY KEY,
  order_id        BIGINT UNIQUE REFERENCES customer_orders(id),
  packed_by       INTEGER REFERENCES users(id),
  box_count       INTEGER DEFAULT 1,
  total_weight_kg FLOAT,
  packing_slip_ref VARCHAR(50),
  status          VARCHAR(15) DEFAULT 'pending',
  completed_at    TIMESTAMPTZ
);

-- Step 7: Quality checks
CREATE TABLE quality_checks (
  id              BIGSERIAL PRIMARY KEY,
  order_id        BIGINT UNIQUE REFERENCES customer_orders(id),
  checked_by      INTEGER REFERENCES users(id),
  result          VARCHAR(15),
  items_checked   INTEGER DEFAULT 0,
  items_passed    INTEGER DEFAULT 0,
  items_failed    INTEGER DEFAULT 0,
  failure_reasons JSONB,
  action_taken    VARCHAR(20),
  checked_at      TIMESTAMPTZ
);

-- Step 8: Dispatch records
CREATE TABLE dispatch_records (
  id                 BIGSERIAL PRIMARY KEY,
  order_id           BIGINT UNIQUE REFERENCES customer_orders(id),
  carrier_name       VARCHAR(100),
  tracking_number    VARCHAR(100),
  dispatch_method    VARCHAR(20) DEFAULT 'courier',
  dispatched_by      INTEGER REFERENCES users(id),
  dispatched_at      TIMESTAMPTZ,
  estimated_delivery TIMESTAMPTZ,
  status             VARCHAR(15) DEFAULT 'pending'
);

-- Step 9: AI decision log
CREATE TABLE fulfillment_decisions (
  id               BIGSERIAL PRIMARY KEY,
  order_id         BIGINT REFERENCES customer_orders(id),
  stage            VARCHAR(50),
  problem_detected TEXT,
  recommendation   TEXT,
  action_taken     VARCHAR(20) DEFAULT 'manual_review',
  confidence_score FLOAT,
  llm_model        VARCHAR(80),
  created_at       TIMESTAMPTZ DEFAULT NOW()
);

-- Step 10: Stage transition log
CREATE TABLE order_stage_log (
  id           BIGSERIAL PRIMARY KEY,
  order_id     BIGINT REFERENCES customer_orders(id),
  from_status  VARCHAR(30),
  to_status    VARCHAR(30),
  triggered_by INTEGER REFERENCES users(id),
  trigger_type VARCHAR(15) DEFAULT 'manual',
  notes        TEXT,
  created_at   TIMESTAMPTZ DEFAULT NOW()
);

AI Decision Engine

LangChain + Gemini 2.0 Flash — free, fast, JSON-structured decisions

backend/services/decision_engine.py 
import os, json
from langchain_google_genai import ChatGoogleGenerativeAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

llm = ChatGoogleGenerativeAI(
    model=os.getenv("GEMINI_MODEL", "gemini-2.0-flash"),
    google_api_key=os.getenv("GOOGLE_API_KEY"),
    temperature=0.1,
    max_output_tokens=512,
)

DECISION_PROMPT = ChatPromptTemplate.from_messages([
    ("system", """You are a warehouse fulfillment AI.
Analyze the order data and respond ONLY with valid JSON.
No markdown, no explanation, just the JSON object.

JSON format:
{{
  "problem_detected": "string or null",
  "recommendation": "string",
  "action": "proceed|hold|reassign|recheck|cancel|escalate",
  "confidence": 0.0-1.0,
  "auto_apply": true|false
}}

Rules:
- auto_apply false if confidence < 0.85
- auto_apply false for cancel/escalate
- Be conservative: prefer hold over proceed when uncertain"""),
    ("human", "Stage: {stage}\nOrder data: {context}\nSystem flags: {flags}")
])

def analyze_stage(order_id: int, stage: str, context: dict, flags: list, db) -> dict:
    if os.getenv("AI_ENABLED", "true") != "true":
        return _rule_based_fallback(stage, context, flags)
    try:
        chain = DECISION_PROMPT | llm | StrOutputParser()
        result = chain.invoke({
            "stage": stage,
            "context": json.dumps(context, default=str),
            "flags": ", ".join(flags) if flags else "none"
        })
        decision = json.loads(result.strip())
        _save_decision(order_id, stage, decision, db)
        return decision
    except Exception as e:
        return _rule_based_fallback(stage, context, flags)
🎯 Per-Stage Analysis

Separate analysis function for each stage: analyze_inventory_check, analyze_allocation, analyze_picking, analyze_packing, analyze_qc, analyze_dispatch. Each builds a context dict from the DB and calls analyze_stage.

🛡️ Rule-Based Fallback

When AI_ENABLED=false or Gemini API fails, the system falls back to deterministic Python if/else logic. Zero downtime, same response shape. Critical for rate limit handling on free tier.

3
Decision Engine + Gemini Setup
~2h ▼

Install: pip install langchain-google-genai google-generativeai. Get free API key from aistudio.google.com. Build backend/services/decision_engine.py with per-stage analysis functions and rule-based fallback.

Fulfillment Routers (7 files)
~4h ▼

Build in order: orders.py → allocation.py → picking.py → packing.py → quality.py → dispatch.py → fulfillment_dashboard.py. Each router calls the decision engine on stage transition. Dispatch router triggers inventory deduction.

Add to frontend/pages/: orders.html (order list + priority badges + SLA countdown), order-detail.html (pipeline progress + tabs), picking-board.html (kanban), fulfillment-dashboard.html (KPIs + alerts). Update layout.js sidebar.

6

~1h ▼

Run test_fulfillment_pipeline.py: create order → priority score → allocate → pick → pack → QC pass → dispatch → verify stock deducted. Check order_stage_log has 8 entries and fulfillment_decisions has ≥6 records.

Common Pitfalls

Things that will break the build if you miss them

🔴
Gemini returns markdown-wrapped JSON
Strip backtick fences before json.loads(): result.strip().replace("```json","").replace("```","")
🔴
db.commit() inside allocation loop
Batch all allocation inserts, commit once after loop. Committing per-iteration causes partial writes on exception.
🔴
Dispatch deducts from wrong column
On dispatch: decrement on_hand AND decrement reserved_qty by the same amount. Don't zero reserved_qty separately — it must balance.
🟡
Supabase connection pooling
Use port 6543 (PgBouncer pooler) not 5432 (direct). Set pool_pre_ping=True in SQLAlchemy create_engine for resilience.
🟡
Gemini rate limits on free tier
Add exponential backoff with 3 retries. If retries exhaust, fall through to rule-based fallback — never crash the request.
🟡
Pydantic v2 breaking change
Use model_config = ConfigDict(from_attributes=True) — not class Config: orm_mode = True (removed in v2).
🟢
SLA countdown timers in frontend
Use setInterval at 60s. Format as Xh Ym remaining. Apply color: red class when remaining < 6h. Clear interval on page unload.
